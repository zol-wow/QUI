Core idea

Ask intent first, configure second

A full-pane wizard replaces the popup. Each step asks one plain-language question; answers compile into the same Display data the editor already understands. QUI has precedent: the role-based Setup Wizard for unit/group frames (core/aura_wizard.lua) — it just never reached Aura Displays.

Design contract

Nothing the wizard writes is special. The result is an ordinary Display — open it in the classic 3-tab editor and every choice is just a pre-filled field.

Honest accounting

What it fixes — and what it doesn't

A wizard is a front door, not a renovation. Worth being precise about which pain numbers it actually moves.

Fixes
  • First-run dread. 4 questions instead of 35–40 controls staring back at you.
  • The defaults bug. AD.DefaultBucket (32px, 12pt duration) is finally applied on creation instead of discarded.
  • Center-spawn drag ritual. The 9-zone picker places displays roughly right on the first try.
  • Discoverability of "What to Show". Goal cards surface Dispellable / Boss debuffs / Helpful without opening a 46-row form.
  • Spell-ID hunting. Spec-aware suggestions replace alt-tabbing to Wowhead for your first display.
Doesn't fix
  • Editor complexity afterwards. The 80–120 widget editor is untouched; the wizard just delays your meeting with it.
  • Wizard fatigue. By display #20, four steps is friction. Mitigated by "Create another" carrying settings over, and the blank-display escape hatch — but not eliminated.
  • No sharing story. Still no templates, no per-display import/export. (Approaches 2 and 5 attack this.)
  • Groups stay organization-only. No shared layout or styling falls out of this.
Implementation notes

Mostly plumbing that already exists

  • Reuse quick-create plumbing LOW The wizard's final "Create Display" calls the same creation path as today's popup — kind, spells, name, unit are the identical payload, plus style/position/load fields the editor already owns.
  • Apply AD.DefaultBucket on create LOW The tuned defaults (32px icons, 12pt duration text) exist in code today and are simply not wired into quick-create. Worth shipping as a standalone bugfix even if the wizard never happens.
  • Wizard shell precedent MED core/aura_wizard.lua already implements a role-based setup wizard for unit/group frames — step navigation, full-pane layout, and apply-on-finish patterns to crib from.
  • 9-zone position picker MED Maps to anchor point + offset presets; hands off to the existing Layout Mode for fine-tuning. New UI, but small surface.
  • Spec-aware spell suggestions HIGH — biggest content cost Needs a curated table of suggestion-worthy spells per spec (13 classes × ~3 specs). Not hard code, but real authoring and upkeep every patch. Ship v1 with the wizard minus chips if needed; the search box alone still beats a bare spell-ID field.
Verdict

Steal this if the #1 goal is
first-display success rate.

The wizard converts "which of these 40 controls matters?" into four questions a first-timer can answer from intent alone — and quietly fixes the worst current bug (discarded defaults) along the way.

It deliberately does not make the editor simpler or add sharing; it makes the entrance survivable. Pairs naturally with any of the other four approaches — the goal cards in Step 1 are an obvious mounting point for templates or recipes.
