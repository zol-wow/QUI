The core idea

Nobody should start from a blank display

Replace the popup as the front door. "New Display" opens a gallery; the blank form becomes the last card, not the first experience.

  1. Gallery first. Curated starter templates — single displays and whole groups — with live-looking previews. You pick an outcome, not a form.
  2. Spec-aware. Templates are tagged by class / spec / role. A Mistweaver sees Mistweaver things first, under a "For you" chip.
  3. Installed, not explained. One click writes a real display (or group) through the existing store, pre-sized, pre-filtered, pre-positioned. Then you tweak it in the normal editor — same tabs, same everything.
  4. Escape hatch preserved. "Blank Display" is always the final card and opens today's popup unchanged.
New Display→ Gallery→ Pick a card→ Confirm + position→ Editable displays on screen

Under the hood

A template is a saved display wearing tags

Same data format as any serialized display/group, plus a placement hint and targeting tags. No new schema, no parallel editor.

["tank-defensives"] = { name = "Tank Defensives", tags = { role = "TANK" }, -- or class = "MONK", -- specID = 270 … placement = "BOTTOM_CENTER", -- hint, not a lock payload = { --[[ serialized group + displays; the same shape profile export already writes for "Aura Displays" ]] }, }

Install = deserialize payload → existing NewDisplay / group CRUD → apply placement. Templates can't drift from the editor because they are editor data.

Honest ledger

What this fixes — and what it doesn't

Fixes

  • Instant value. A working, well-placed display in ~10 seconds instead of a blank form and 35–40 controls.
  • Discoverability. Cards advertise what the feature can do — Co-Tank unit, "Dispellable by me", boss-debuff strips — capabilities currently buried in dropdowns.
  • Kills the bad-defaults bug in practice. Templates carry 32px icons and duration text on; nobody ships 16px accidents.
  • Per-display import/export falls out for free, plus a path to community content and cross-alt reuse.

Doesn't fix

  • Curation is an ongoing commitment. Every patch, every spec rework, someone must review the table. This is content work, not code work.
  • Templates rot. Renamed/removed spells make a curated card feel broken — worse than no card.
  • The editor is untouched. The moment you tweak, you're back in the 80–120-widget, 3-tab reality. Templates soften the start, not the middle.
  • Coverage gaps read as neglect. A spec with zero "For you" cards feels like a second-class citizen.
Implementation notes

Mostly plumbing that already exists

  1. Data model: none new. Template = serialized display/group + placement hint + tags. Install path is the existing store CRUD (NewDisplay, group create/assign) — templates land as ordinary saved displays.
  2. Serialization: scoped-down profile export. profile_io already serializes the "Aura Displays" category for whole-profile strings; per-display/per-group strings are the same routine on a narrower table, plus a !QUI:AD1: envelope with a version byte.
  3. Gallery UI: one new panel. Cards render from a static curated Lua table; previews are lightweight mock renders (icon/bar chrome), not live aura data — cheap and deterministic.
  4. The real cost is the curated table. Budget it: start with ~3 generic templates per role + 2 per class (~45 cards), tagged, reviewed once per major patch. "Mine" + import strings absorb the long tail so curation never has to be complete.
  5. Escape hatch: zero migration risk. The Blank Display card calls today's popup verbatim; existing displays and profiles are untouched.
Verdict

Steal this if you want the feature to sell itself in 10 seconds.

Effort

Medium. UI panel + serialization envelope are days; the curated table is the ongoing line item.

Payoff

Highest day-one impact of the five approaches: first-run experience goes from blank form to working HUD.

Risk

Content maintenance. Mitigate with a small generic core + "Mine" + community strings.

Pairs well with Approach 1 (wizard) as the card→confirm step, and Approach 3 (simple mode) for the after-install editing story.
