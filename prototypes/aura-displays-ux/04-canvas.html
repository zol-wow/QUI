Invert the surfaces: the screen is the editor

Direct manipulation for everything spatial. A compact inspector for the next tier. The panel for the rest.

1 · The game screen

Position, size, grow direction, spacing — grabbed, dragged, and seen live. Labeled outlines, snap guides, preview data. Nothing spatial is a number anymore.

2 · Contextual inspector

Click a display, get a popover with ~8 controls: name, unit, size, grow, spacing, icon count, glow. The highest-value settings, right where you're looking.

3 · Options panel

Still the deep editor — STRIP filters ("What to Show"), Load Conditions, text styling, bar Thickness/Length/Orientation. Reached via All settings… on any display.

Two views, one data model. The inspector and the panel write to the same store — and Aura Displays already register anchors in Layout Mode, with a per-display Preview toggle that fakes icons. The foundation exists; this deck extends it.

What it fixes — and what it honestly doesn't

Fixes

  • Geometry becomes self-evident. Anchor / Grow / Offsets — the least learnable ~third of the form — stops being a form at all.
  • Creation friction near zero. Place, name a spell, done. No 35–40-control page for a first display.
  • The split-brain is gone for everything spatial: no more panel ↔ Layout Mode round-trips.
  • Bad defaults die on contact. A 16px quick-create icon is instantly visible as too small — and one slider-drag fixes it.

Doesn't fix

  • Non-spatial config still needs the panel: STRIP filters ("What to Show"), Load Conditions (Roles/Classes/Specs/Encounters), text styling, bar orientation details.
  • A robust on-screen inspector in WoW's UI toolkit is significant work — popover layout, clamping, input focus, scaling.
  • Discoverability of the mode itself becomes the new problem: users must learn Edit Displays exists.
  • Combat lockdown: secure-frame restrictions mean editing is out-of-combat only.
Out of combat only — WoW restriction, mode refuses to open in combat Esc exits cleanly, like Layout Mode today One data model — canvas edits mirror to the same store the panel edits

Implementation notes

This is an extension of machinery QUI already ships, not a new subsystem.

Builds on Layout Mode

Aura Displays already register per-display anchors under the "Aura Displays" mover group. Edit Displays = Layout Mode + selection + inspector. The per-display Preview: On/Off becomes the toolbar's "Preview data".

Inspector stays small

~8 highest-value settings only — name, unit, size, grow, spacing, count, glow — writing straight to the existing store. Everything else defers to the panel via All settings…. Resist scope creep here.

New but self-contained

Snap guides (center/edges + toast) are net-new but isolated. The inline creator reuses quick-create plumbing — and is the moment to fix the 16px default to 32px.

  • Multi-select/align is v2. Ship select-one + inspector + drag/snap + on-canvas create first; align/distribute/group can follow.
  • Entry points: a button in the Aura Displays tab ("Edit on screen…"), the existing Layout Mode, and optionally a slash command.
Verdict

Steal this if the geometry gap is the main wall.

Canvas-First attacks exactly the part users can't learn from a form — where things go and how they grow — and leaves the rest of the form alone. That makes it pair well with any of the other four approaches: the canvas handles space; whatever wins elsewhere handles filters, conditions, and styling.

Cost center: building a solid in-game inspector and snap system. Cheapest credible slice: selection outlines + drag/snap + the 8-control inspector, with creation still in the panel.
